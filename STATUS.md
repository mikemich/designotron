## What doesn't work yet / known limitations

| Area             | Limitation                                                                                               |
|------------------|----------------------------------------------------------------------------------------------------------|
| Background service | Linux unit tested; the macOS launchd agent hasn't been run on a real Mac yet. Windows has no background service (run `designotron.exe`) |
| Collaboration    | The public relay is a free Render instance (sleeps when idle, first share wakes it in up to a minute); concurrent edits to the same property of a layer, style, variable mode value or page field: the one the relay receives last wins (different ones both stick, and everyone ends up with the same file; older relays fall back to last writer wins per layer and per whole list); a collection's modes and a page's layer order travel whole; relays older than Wave 2 reject files and changes that use baseline alignment, so update the relay before editors use it; on a relay older than Wave 3 there are no view-only links, Wave 3 changes are sent downgraded (angular/diamond as radial, crop as fill, new triggers and transitions as their nearest old ones) and fields the old relay doesn't know (gradient handles, per-side strokes, variable scopes, effect/grid styles, scrolling) are dropped for people who join later; an old editor that sends whole style lists wipes effect and grid styles; links are the only access control (no accounts); versions live only in each browser. Relay limits stop single clients, not distributed abuse; messages still uploading aren't counted in the memory budget; on the free relay one large file with several people can fill the budget on its own (WebSocket buffers keep a copy's worth per editor), so it caps shared files at 20 MB |
| Two tabs         | One editing tab per file (Web Locks); other tabs show it read-only and follow its saves. "Edit here anyway" (after 5 s without an answer) can lose the old holder's unsaved edits; that tab keeps them on screen with a .dtron download until discarded. A tab that loses the lock between its write starting and the take-over is only stopped once it hears of it (a very small window). Undo history is cleared when a tab reloads from storage (taking over, giving up the lock). Memory mode (storage never worked) keeps only this session's index entries until the probe finds storage again, and the copy back never overwrites records another tab stored. A live session on the editing tab refuses hand-offs; a tab that joins a session is not held back |
| Storage          | Projects and folders live in this browser only: they don't travel in `.dtron` files, Send a copy, view or live links (copies land in Drafts); no multi-select, trash or manual ordering; Drafts has no folders. A tab still running an older version of the app rebuilds index entries without `folder`, so its next save moves that file to Drafts. Clicking "Keep it" at the exact moment another tab finishes deleting the same file can leave a listed file with no content (millisecond window). Files live in the browser (IndexedDB). Clearing site data deletes them; save `.dtron` files to keep them. A file whose content sits in one huge top-level frame rewrites that frame on every save; auto versions (every 10 min) and the bridge document push still serialise the whole file; two tabs on one file are one editing tab and read-only others (see the Two tabs row); without Web Locks every tab edits and the last save wins, whole; a Duplicate from the files list while the file's last save is still writing can miss the last edits |
| Scale            | Updates are incremental, but the canvas is one big SVG: painting 10k+ layers zoomed out is the limit. Text under 5 px on screen is drawn as bars and off-screen top-level layers aren't laid out; at 20k layers zoom p95 is ~200 ms and a few selection clicks still exceed 50 ms in software rendering |
| Text             | No OpenType features or per-range line height; widths depend on the web font having loaded               |
| URL import       | Scripts don't run, so sites rendered by JavaScript come in mostly empty; very long pages make many layers |
| Headless text    | Bridge headless mode measures text with a heuristic, so layout can differ slightly from the editor       |
| Strokes          | Inside/outside alignment is exact for rectangles/ellipses; other shapes clip or fall back to center      |
| Effects          | Background blur is not drawn on the canvas (exported to code as `backdrop-filter`)                       |
| Paint            | Diamond gradients in CSS are an approximation; per-side outside/centre strokes in code are offset box-shadows without corner squares; dashes don't apply to individual strokes; translucent angular stops show faint seams; the linear width handle has no visual effect; Crop mode exists only while the paint's popover is open |
| Tools            | The layers-panel context menu lacks the Wave 3 selection commands; the eyedropper doesn't blend layers and samples external `http` images as a placeholder; Ctrl+Alt+T (Tidy up) is taken by the OS on Linux/ChromeOS (use the Edit menu) |
| Vectors          | Edit mode adds points (click a segment, exact Bézier split; segments only a few pixels long still take one in their middle, because anchors there shrink their hit area and hide their control handles until selected), deletes points (select, Delete), toggles sharp/smooth (double-click) and continues open paths with the pen; no bend tool yet; inside auto layout the box refit after an edit is overwritten by the layout; boolean results are flattened (not live) and curves become polylines; text can't be flattened |
| Masks in code    | A frame or group containing a mask is exported to code as inline SVG                                     |
| Components       | Layers are matched on a swap by their name path (repeated names pair up in order): an override on a layer the new component lacks, or whose name changed, is dropped; an edit that puts back the main component's value counts as no override |
| Components       | An instance swapped concurrently by two people can show a mix of both variants' layers (changes merge field by field) until it is next re-synced; everyone, and the relay, sees the same thing. Of two concurrent changes to one instance's component, overrides or property values the later in the relay's order wins as a whole. Component properties have no preferred values; bound layers inside an instance can't be bound again; only an instance placed directly in a main component can expose its properties; Figma import doesn't bring component properties |
| Multi-resize     | Resizing several rotated layers at once approximates their new boxes                                     |
| Prototyping      | Smart animate matches only direct children (stage 1); no sticky, On drag, springs, Reset component state or variables; fixed layers only in a scrolling top-level frame; the editor canvas doesn't preview scrolling; text links aren't clickable in Presenter or the view link; overlays always render at the frame's design size and don't scroll |
| Tests            | `markdown.test.ts` "is fast on hostile input" is timing-sensitive and can fail under load (also on older commits) |
| Photos           | Headless MCP (no editor tab) answers `search_photos`/`place_photo` with "needs the editor open": the browser downloads and embeds the photo. Unsplash is not offered (its guidelines require hotlinking, we embed bytes); the provider code is shaped so it can be added later. Openverse allows about 200 anonymous searches a day per address and 20 a minute (the panel says so on a 429); Pexels has no safe-search switch and needs your own key; licence data comes from the providers and can be wrong, so Inspect links the source page. Relays older than this change drop `credit` when they re-serialise paints (redeploy the relay, to-do 1). "Send a copy" and Share → Copy link drop images over about 400 KB, and one 1600 px stock photo can reach that, so shared copies may arrive without their photos. Not tested against the live provider APIs or with real keys. The left panel (Assets) is hidden on phones, so there is no photo search there |
| Images           | External `http` image URLs render on canvas but are missing from PNG export (assets are fine)            |
| HTML import      | Auto layout is only used where the engine reproduces the browser's boxes within 2px: uneven margins between siblings, per-child `align-self`, proportional `flex-grow`, fr-based grid sizing and tables stay absolute or fixed-size. Inline elements with their own box (`sup`/`sub`, inline-block buttons, svg icons in links, shadows or side margins) stay separate layers; a merged chip loses its background and border (its width is kept as letter spacing); highlight-only spans lose the highlight; pre-wrap text keeps the old path; `text-transform` capitalize/lowercase is ignored; relative links in pasted HTML are dropped |
| Bridge sync      | Only the focused tab mirrors to `design.dtron.json`; if MCP edits happen with no editor open, a tab that connects later pushes its own document over the file when it becomes active |
| Security         | API key (API mode) is stored in this browser's localStorage                                              |
| Input            | No touch/pen support. Keyboard-only and screen-reader use work for the editor and dashboard, but at 200% browser zoom the editor switches to the phone layout (no layers or design panel), several targets are under 24px and some text is 11px |
| Figma            | Import needs the REST API (no `.fig` files); library components become frames; fonts missing locally fall back; FigJam and Slides are not implemented |
| Device frames    | Insets reach code only on auto layout device frames; editing `layout` with a merge patch does not re-pad (use the Device section, or Shift+A / remove auto layout, which do); a relay older than this build drops the device marks for late joiners, who then get the chrome as plain layers that code export includes; absolute-positioned device frames export their design coordinates; chrome fonts are Inter and Roboto, not SF, and the status bar is an approximation drawn from common design kits; editing the time on one screen does not spread to the others; typing a padding value in the Design panel on a padded device frame sets the total, safe area included; two people running a device change at the same moment can leave two sets of chrome until the next device change; frames resized by auto layout itself (hug or fill) still don't apply child constraints, only explicit resizes do; iPhone SE has no on-screen home indicator (it has a button); unverified preset values (iPhone SE, Android and Galaxy sizes and insets, iPad insets other than the mini, MacBook Air sizes, Mac window and browser chrome sizes, chrome geometry) are listed in the `devices.rs` comments |
| Plugins          | Run in a sandboxed iframe; browsers that keep it in the editor's process (not Chromium) freeze the tab if a plugin loops forever. A plugin that stops answering is flagged with Stop. Plugins can't load anything from the web (CSP, refused tools and web addresses, so prototype "Open link" URLs can't be set from one; image paints accept only asset:, data:image/ and absolute http(s):// sources), but a malicious plugin can still send data out by navigating its own frame (it is stopped on the second load, after the request went out); inline `on*=` handlers in plugin UI HTML don't run; no per-plugin permissions or manifests yet |
| Figma API        | Not tested against a real Figma account here (no token); the converter is tested on REST-shaped JSON     |
