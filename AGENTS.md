# AGENTS.md

This file provides guidance for coding agents when working with the Designotron monorepo.

## Project Overview

Designotron is a free, open-source design tool (a Figma alternative) with Claude built in.
The document engine is Rust: it compiles to WebAssembly for the browser editor and links
natively into a local bridge server. A thin TypeScript/React shell provides the UI.

Claude integrates in two ways, both driven by one tool layer (`crates/engine/src/ai.rs`):

- **Claude Code (Pro/Max)**: the bridge exposes the editor as an MCP server and spawns the
  user's own `claude` CLI for in-app chat. Never put a claude.ai login inside the app; the
  subscription is only ever used through the user's Claude Code install.
- **API key**: the browser calls the Messages API directly with a user-supplied key.

Track progress in [STATUS.md](STATUS.md) and follow the order of work in [ROADMAP.md](ROADMAP.md). Update STATUS.md in the same change whenever you finish,
start or break something.

│   ├── bridge/              # Local server: editor websocket, MCP, Claude Code chat, LAN share
│   └── relay/               # Internet relay for online multiplayer (+ serves the editor)
├── web/                     # Editor shell (Vite + React + Zustand)
│   ├── src/
│   │   ├── store.ts         # Boots WASM, wraps the engine, UI state
│   │   ├── canvas/          # Canvas, overlays, tools, text editor

│   │   ├── ai/              # Chat panel, bridge client, API agent, browser-only tools

`target/`, `web/node_modules/`, `web/dist/` and `workspace/` are build or runtime output and
must never be committed.

## Architecture Rules

- The Rust engine is the single source of truth for the document. The web shell never
  mutates the document itself; it sends a `Command` and re-reads state.
- Every mutation is a `Command` variant in `engine.rs`. One command is one undo step.
  Pointer drags wrap their commands in `beginGesture` / `endGesture`; gesture-relative
  commands (`translate`, `resize`, `rotate`) always apply from the gesture's base state.
- Generic property edits go through `Command::Update` with a JSON merge patch
  (`patch.rs`). Add a dedicated command only for structural changes.
- AI tools are defined and executed in `ai.rs` only. The chat API agent, the MCP server
  and headless mode all call it. Browser-only tools (`get_screenshot`, `import_html`) live
  in `web/src/ai/` and are listed in `ai::BROWSER_TOOLS`.
- The canvas and exports share `render.rs`. Do not add a second renderer.
- Image bytes never enter the document: paints reference `asset:<id>` and the bytes live
  in `web/src/assets.ts` and the `.dtron` file's `assets` map.
- When `model.rs` changes, update `web/src/types.ts` in the same change.
- The bridge binds to 127.0.0.1 and checks `Origin` / `Host` (`security.rs`). Keep it that
  way; the bridge can run Claude Code with write access.
- Performance model: `Document::nodes` is a persistent `imbl::OrdMap`, so clones are O(1) and
  `prev.nodes.diff(&doc.nodes)` costs only what changed. Layout, component fingerprints, the
  canvas render cache (`render_incremental`) and the JS document copy (`doc_delta`) all work
  from that diff. Only `get_mut` nodes you actually change (use `Document::update_where`), and
  never add per-mutation or per-frame work that scans every node.
- Room logic lives in `crates/rooms`, used by the bridge (one LAN room) and `crates/relay`
  (many online rooms keyed by an unguessable id). The relay only stores and relays
  documents: never add tools, MCP or Claude to it.
- Multiplayer (`collab.rs` in engine and bridge): peers exchange `collab::delta` JSON; remote
  changes enter through `Command::ApplyRemote` and never join local history. Undo/redo use
  `collab::revert`, so a step only reverses its own changes. Any new document-level field must
  be handled in `collab::delta`, `apply` and `revert`. The LAN share listener serves only the
  editor and `/collab/ws` behind the token; never add MCP, chat or fetch routes to it.
- The canvas patches one `<g data-root>` per top-level layer; a root whose only change is its
  position gets a transform update instead of new markup. `.canvas` uses `contain: strict` and
  its SVGs are sized in pixels so panel updates never re-lay out the canvas.

## Commands

```bash
cargo test --workspace                 # Engine + bridge unit tests
cargo clippy --workspace               # Lints
cd web && npm run wasm                 # Rebuild web/src/wasm/pkg after engine changes
cd web && npm run typecheck            # TypeScript (tsc -b, same as the production build)
./dev.sh                               # Bridge on :5174 + editor on :5173
cd web && npm run e2e                  # Editor smoke test (needs ./dev.sh running)
cd web && node scripts/bridge-e2e.mjs  # MCP + live editor (E2E_CLAUDE=1 adds a real chat turn)
cd web && node scripts/collab-e2e.mjs  # Multiplayer with two browsers (bridge serving web/dist)
cargo run -p designotron-relay -- --static web/dist   # Online relay on :8787 (E2E_RELAY=… for the e2e)
cargo run --release -p designotron-engine --example bench   # Engine timings on a 6k-layer file
cd web && node scripts/perf.mjs [frames] [cards]           # Browser drag timings (PROFILE=1, TRACE=1)
```

After changing anything under `crates/engine`, run `npm run wasm` and commit the regenerated
`web/src/wasm/pkg` so the editor works without a Rust toolchain.

## Code Style

- Rust 2021 edition, two-space indentation (see `rustfmt.toml`)
- Never use `println!` or `eprintln!` outside of tests; use `log` crate macros instead
- Engine crate stays dependency-light (`serde`, `serde_json`, `imbl`, `i_overlay`) and
  platform-free; no I/O
- The engine `Engine` type is not `Send`; in async code keep it inside a sync helper and
  never hold it across an `.await`
- When two crates export the same type name, alias imports with a suffix: `use foo::Bar as BarFoo;`
- Prefer `use` imports over inline fully-qualified paths; only qualify inline for true one-offs or std collisions
- Serde types use `#[serde(rename_all = "camelCase")]`; JSON crossing to TypeScript is camelCase
- TypeScript with React, Vite and Zustand; two-space indentation; no React StrictMode
  (editor effects open and close undo gestures)
- UI talks to the engine only through `dispatch`, `query` and `getDoc` in `store.ts`

### File Layout

Organize for top-to-bottom reading. Important things first, details later.

- **Constants** at the top (after imports)
- **Structs/enums** next; outer structs above inner sub-structs
- **API types** in order: Request, Response, Error
- **In impl blocks**: constructors first, then public methods, then private helpers
- Private helpers go *below* the methods that call them
- Among helpers: meatier logic above leaf-level formatters
- **In test modules**: constants first, then test cases (grouped into sub-modules when 2+), then helper functions last

## Testing

- Every engine behaviour gets a unit test next to it (`#[cfg(test)] mod tests`).
- UI changes that touch tools, selection or panels should keep `web/scripts/e2e.mjs`
  passing; add a check there for new user-facing behaviour.
- Claude integration changes should keep `web/scripts/bridge-e2e.mjs` passing.

## Markdown

- **Tables must be space-padded so columns align in plain text.** Markdown
  tables are read raw (terminals, diffs, editors) at least as often as
  rendered, and condensed tables are unreadable there. Pad every cell to its
  column width:

  ```markdown
  | Feature      | Status  | Notes                  |
  |--------------|---------|------------------------|
  | Auto layout  | Done    | Hug, fill, wrap        |
  | Multiplayer  | To do   | Planned via CRDT       |
  ```

  Not: `| Feature | Status | Notes |` packed tight with varying widths per row.
